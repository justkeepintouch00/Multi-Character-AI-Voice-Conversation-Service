# 2026-08-12 작업 기록

## 완료

- 캐릭터 생성·조회·수정 API와 PostgreSQL 저장 구조를 연결했다.
- C모드 화면에서 캐릭터 API로 대화를 생성하고 사용자 발화를 대화 API로 전송하도록 연결했다.
- C모드에 브라우저 음성 인식(Web Speech API)을 연결했다. 한국어(`ko-KR`) 인식 결과가 확정되면 현재 대화 API에 전송된다.
- C모드의 최신 캐릭터 발화를 장면 하단에 한 건만 표시하도록 화면을 정리했다.
- 기본 개발 캐릭터 루미와 캐릭터 B의 콘셉트에 반말 사용 조건을 추가했다.
- 장면 흐름 편집 화면에서 다음 장면 연결과 분기 표시를 정리했다.
- 백엔드 메시지 저장 순서 문제를 수정했고, 이전 검증에서 백엔드 테스트 36개 통과·1개 스킵, PostgreSQL 통합 테스트 통과, 프론트 빌드·린트 통과를 확인했다.
- 캐릭터·C모드·평가용 골드셋과 평가 스크립트를 GitHub PR #6 브랜치에 반영했다.

## 현재 제약 및 다음 작업

- 현재 C모드 음성 입력은 브라우저 Web Speech API 기반이다. Groq STT 파일 업로드 경로를 이용하는 녹음 입력은 아직 C모드 화면에 연결되지 않았다.
- Typecast TTS 자동 재생은 아직 C모드 화면에 연결되지 않았다. 음성 대화 MVP를 위해서는 `음성 녹음 → STT → 대화 API → TTS 자동 재생`을 하나의 흐름으로 연결해야 한다.
- C모드의 시작 장면은 기획서에 정의된 낮은 부담의 일상 대화와 두 선택지를 반영하도록 추가 정비가 필요하다.
- 말투는 캐릭터 설정 값(`speech_style`)을 Scene Director 프롬프트에서 강하게 준수하도록 보완이 필요하다. 현재 콘셉트 문구만으로는 존댓말/반말 일관성을 보장하지 않는다.
- 자동 발화 감지(VAD)는 아직 구현하지 않았다. 현재 브라우저 음성 인식의 발화 종료 판단에 의존한다.
