# 삭제 보류 후보 목록

이 문서는 현재 삭제하지 않는 항목을 눈에 보이게 유지하기 위한 목록이다. 아래 항목은 실제 실행 경로·마이그레이션·향후 운영 설계에 영향을 줄 수 있으므로, 명시적 승인 전에는 삭제하지 않는다.

## 이미 제거된 Docker 전용 구성

- `observability/docker-compose.yml`
- 로컬 Prometheus·Grafana provisioning·Alloy Docker 구성
- 로컬 관측성 로그 파일 설정

Grafana Cloud 방식에는 필요하지 않아 제거했다. 애플리케이션 소스나 대화·메모리 데이터는 제거하지 않았다.

## 삭제 보류

### `Job`, `JobCheckpoint` 모델

- 위치: `backend/app/db/models.py`
- 현재 확인된 사실: API·서비스·저장소에서 생성하거나 조회하는 실행 경로는 확인되지 않았다.
- 삭제하지 않는 이유: 비동기 작업 큐, `job_id` 기반 trace, LangGraph 체크포인트를 영속화할 때 재사용 가능한 데이터 모델이다. 삭제하려면 Alembic 하향/상향 마이그레이션과 운영 DB의 데이터 보존 정책을 함께 결정해야 한다.
- 결정 필요: 실제 비동기 worker를 도입하지 않고 영구적으로 제외할지, 다음 단계에서 job producer/worker를 연결할지.

### `job_id` 관측성 컨텍스트

- 현재 확인된 사실: 관측성 컨텍스트는 `job_id` 필드를 지원하지만, 현재 동기 HTTP 대화 요청은 job을 만들지 않아 값이 비어 있다.
- 삭제하지 않는 이유: 위 `Job` 모델과 같은 판단 단위다. 이번 LangGraph 전환은 요청 내부 오케스트레이션이며, durable worker 실행을 구현한 것은 아니다.

## 삭제 대상이 아닌 기존 파일

- `backend/devtools/20260811_1434_voice_pipeline_test.html`: 문서에서 참조하는 음성 파이프라인 점검 도구다.
- 기존 평가 goldset·평가 스크립트: 현재 기본 평가 입력 또는 결과 비교에 사용된다.

## 다음 삭제 전 확인 항목

1. 운영 DB에 `jobs`, `job_checkpoints` 데이터가 존재하는지 확인한다.
2. 큐 기반 비동기 작업을 도입할지 결정한다.
3. 데이터 보존 기간과 Alembic migration 전략을 결정한다.
