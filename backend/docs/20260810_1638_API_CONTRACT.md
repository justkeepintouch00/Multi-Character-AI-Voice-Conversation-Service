# Character Companion MVP API 계약

> 작성 시각: 2026-08-10 16:38 KST  
> 구현 목표: 2026-09-02 MVP  
> 상태: Health API 구현 완료, 기능 API 계약 초안

## 1. 공통 규칙

- 기능 API 기본 경로는 `/api/v1`이다.
- 운영 상태 확인은 `/health`, `/health/db`를 사용한다.
- 요청·응답은 JSON, ID는 UUID, 시간은 시간대가 포함된 ISO 8601 형식이다.
- 목록 API는 `limit`과 `cursor` 기반 페이지네이션을 사용한다.
- 인증 방식은 아직 `[미확정]`이다. 인증 결정 후 요청의 현재 사용자 문맥으로 데이터 접근 범위를 제한한다.
- 오류에는 내부 예외, DB 주소, 비밀번호, 공급자 비밀키를 포함하지 않는다.

공통 오류 형식:

```json
{
  "error": {
    "code": "RESOURCE_NOT_FOUND",
    "message": "요청한 리소스를 찾을 수 없습니다.",
    "details": {}
  }
}
```

| 상태 | 의미 |
|---|---|
| `200` | 조회·수정 성공 |
| `201` | 리소스 생성 성공 |
| `202` | 비동기 작업 접수 성공 |
| `204` | 삭제 성공 |
| `400` | 잘못된 요청 |
| `401` | 로그인 필요 |
| `403` | 권한 없음 |
| `404` | 리소스 없음 |
| `409` | 현재 상태와 충돌 |
| `422` | 필드 검증 실패 |
| `503` | DB 또는 필수 서비스 사용 불가 |

## 2. Health — 구현 완료

| Method | Path | 설명 |
|---|---|---|
| `GET` | `/health` | FastAPI 프로세스 상태 확인 |
| `GET` | `/health/db` | PostgreSQL에서 `SELECT 1` 실행 |

성공:

```json
{"status": "ok", "database": "connected"}
```

DB 연결 실패 시 HTTP 503:

```json
{"status": "error", "database": "disconnected"}
```

## 3. Character — 다음 구현 범위

API의 `character`는 화면에서 사용하는 캐릭터 aggregate이며 내부적으로 template, version, instance를 함께 다룬다.

| Method | Path | 설명 |
|---|---|---|
| `POST` | `/api/v1/characters` | 사용자 캐릭터 생성 |
| `GET` | `/api/v1/characters` | 현재 사용자의 캐릭터 목록 |
| `GET` | `/api/v1/characters/{character_id}` | 캐릭터 상세 조회 |
| `PATCH` | `/api/v1/characters/{character_id}` | 캐릭터 설정의 새 버전 생성 |

생성 요청 예시:

```json
{
  "name": "루미",
  "nickname": null,
  "concept": "오래된 골목에서 시계 공방을 운영하며 밤에는 혼자 산책하는 캐릭터다.",
  "traits": ["다정한", "차분한"],
  "speech_style": {"honorific": true, "length": "MEDIUM"},
  "relationship_style": "친구 같은",
  "voice_sample_id": null,
  "appearance_asset_id": null,
  "additional_prompt": ""
}
```

검증 규칙:

- `concept`: 50~200자
- `traits`: 최대 4개
- 공개 범위 기본값: `PRIVATE`
- 설정 수정 시 기존 대화의 재현성을 위해 새 character version을 생성한다.

## 4. Conversation

| Method | Path | 설명 |
|---|---|---|
| `POST` | `/api/v1/conversations` | 대화방 생성 |
| `GET` | `/api/v1/conversations` | 대화방 목록 |
| `GET` | `/api/v1/conversations/{conversation_id}` | 대화방과 참여 캐릭터 조회 |
| `POST` | `/api/v1/conversations/{conversation_id}/complete` | 대화 종료 |

생성 요청 예시:

```json
{
  "mode": "TALK",
  "scenario_id": null,
  "character_instance_ids": [
    "00000000-0000-0000-0000-000000000001",
    "00000000-0000-0000-0000-000000000002"
  ]
}
```

검증 규칙:

- `mode`: `PRACTICE`, `SCENARIO`, `TALK`
- 참여 캐릭터는 최소 1명, 데이터 구조상 최대 3명
- 2026-09-02 MVP 화면 활성 캐릭터는 최대 2명
- `PRACTICE`, `SCENARIO`에는 유효한 `scenario_id`가 필요
- 동일 캐릭터를 한 대화에 중복 추가할 수 없음

## 5. Message와 비동기 응답

| Method | Path | 설명 |
|---|---|---|
| `POST` | `/api/v1/conversations/{conversation_id}/messages` | 사용자 메시지 저장 및 AI 작업 접수 |
| `GET` | `/api/v1/conversations/{conversation_id}/messages` | 원본 메시지 목록 조회 |
| `POST` | `/api/v1/messages/{message_id}/interrupt` | 사용자 발화 확정 시 AI 재생 중단 |

요청 예시:

```json
{
  "content": "오늘 면접에서 떨어져서 마음이 복잡해.",
  "input_mode": "TEXT",
  "idempotency_key": "client-generated-unique-key"
}
```

비동기 접수는 HTTP 202와 저장된 사용자 메시지, 생성된 Job을 반환한다.

```json
{
  "message": {
    "id": "00000000-0000-0000-0000-000000000010",
    "speaker_type": "USER",
    "content": "오늘 면접에서 떨어져서 마음이 복잡해.",
    "finalized": true
  },
  "job": {
    "id": "00000000-0000-0000-0000-000000000020",
    "status": "QUEUED"
  }
}
```

Scene Director의 확정 제약:

- 내부 에이전트 처리 단계 최대 5
- 사용자에게 보이는 연속 AI 발화 최대 2
- 처리 뒤 발화권은 기본적으로 사용자에게 반환

## 6. Job

| Method | Path | 설명 |
|---|---|---|
| `GET` | `/api/v1/jobs/{job_id}` | 비동기 작업 상태와 결과 조회 |
| `POST` | `/api/v1/jobs/{job_id}/cancel` | 취소 가능한 작업 취소 |

```text
QUEUED → RUNNING → REVIEWING → COMPLETED
                 ↘ RETRYING → FAILED
QUEUED/RUNNING → CANCELLED
```

동일 사용자와 동일 `idempotency_key` 조합은 메시지와 작업을 중복 생성하지 않는다.

## 7. Memory

| Method | Path | 설명 |
|---|---|---|
| `GET` | `/api/v1/characters/{character_id}/memories` | ACL을 통과한 기억 조회 |
| `POST` | `/api/v1/memories` | 기억 생성 |
| `PATCH` | `/api/v1/memories/{memory_id}/permissions` | know/read/disclose 권한 변경 |
| `DELETE` | `/api/v1/memories/{memory_id}` | 기억 소프트 삭제 |

기억 검색은 유사도 계산보다 ACL을 먼저 적용한다. `can_know`, `can_read`, `can_disclose_to`는 서로 다른 권한이며 A+B 그룹 기억을 C에게 자동 부여하지 않는다.

## 8. Scenario

| Method | Path | 설명 |
|---|---|---|
| `POST` | `/api/v1/scenarios` | 시나리오 생성 |
| `GET` | `/api/v1/scenarios/{scenario_id}` | 시나리오 조회 |
| `POST` | `/api/v1/scenarios/{scenario_id}/runs` | 시나리오를 처음부터 시작 |
| `GET` | `/api/v1/scenario-runs/{run_id}` | 진행 상태와 결과 조회 |

결과에는 사용자가 도달한 결말과 `DID_WELL`(잘한 부분), `TO_IMPROVE`(아쉬운 부분)만 포함한다. 도달하지 않은 결말 정보나 힌트는 응답하지 않는다. 재시도는 장면이 아니라 처음부터 새 run을 만든다.

## 9. 실시간 채널 — 상세 형식 추후 확정

후보 경로:

```text
WS /api/v1/realtime/conversations/{conversation_id}
```

이벤트 후보:

```text
user.partial_transcript
user.final_transcript
assistant.text.delta
assistant.turn.started
assistant.turn.interrupted
tts.chunk.ready
scene.motion
job.status
```

WebSocket/SSE 최종 선택과 음성 원본 저장 여부는 아직 확정하지 않는다.
