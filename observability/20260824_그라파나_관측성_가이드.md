# Grafana Cloud 메트릭 연동 가이드

## 목적

Docker와 로컬 Grafana를 사용하지 않는다. Windows에 설치한 Grafana Alloy가
로컬 백엔드의 `http://127.0.0.1:8000/metrics`를 읽고 Grafana Cloud Metrics로 전송한다.

평가 대시보드는 실험별 품질·성능 비교용이고, Grafana Cloud는 실행 중인 서버의
요청률·지연시간·오류·LLM 사용량을 시간 흐름으로 보는 운영용이다.

## 1. 백엔드 확인

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
python -m uvicorn app.main:app --reload
```

브라우저에서 <http://127.0.0.1:8000/metrics>를 열어
`character_companion_http_requests_total`이 보이는지 확인한다.

## 2. Grafana Cloud에서 값 준비

1. Cloud Portal에서 현재 stack의 `Launch`를 눌러 Grafana 화면으로 이동한다.
2. `Connections`에서 Grafana Alloy를 찾고 Windows 설치 안내를 연다.
3. Cloud Portal의 `Details`에서 Prometheus details를 열어 다음 두 값을 복사한다.
   - Metrics URL: `.../api/prom/push` 주소
   - Metrics instance ID
4. Cloud Portal의 `Security > Access Policies`에서 stack 범위의 새 정책과 토큰을 만든다.
   - 이름 예시: `character-companion-local-metrics`
   - 최소 권한: `metrics:write`

토큰은 한 번만 표시될 수 있으므로 비밀번호 관리자에 보관한다. 저장소·채팅·화면 공유에 넣지 않는다.

## 3. Windows Grafana Alloy 설치

관리자 PowerShell에서 실행한다.

```powershell
winget install GrafanaLabs.Alloy
```

설치가 끝나면 기본 설정 파일은 다음 위치에 있다.

```text
C:\Program Files\GrafanaLabs\Alloy\config.alloy
```

## 4. 프로젝트 메트릭 수집 설정

`observability/alloy/grafana-cloud-metrics.alloy.example` 파일 내용을 위
`config.alloy`에 복사한다. 다음 세 placeholder를 Cloud에서 복사한 값으로만 바꾼다.

- `REPLACE_WITH_GRAFANA_CLOUD_METRICS_URL`
- `REPLACE_WITH_GRAFANA_CLOUD_METRICS_INSTANCE_ID`
- `REPLACE_WITH_GRAFANA_CLOUD_ACCESS_POLICY_TOKEN`

설정을 저장한 뒤 `services.msc`를 열고 `Alloy` 서비스를 다시 시작한다.
Alloy 서비스가 실행되면 Cloud로 15초마다 메트릭을 전송한다.

## 5. Cloud 대시보드 가져오기

1. Grafana Cloud에서 `Dashboards > New > Import`를 연다.
2. `observability/grafana/dashboards/character-companion-overview.json`을 업로드한다.
3. 가져오기 화면에서 Prometheus 데이터 소스로 Cloud Prometheus를 선택한다.
4. `Import`를 누른다.

처음에는 데이터가 없을 수 있다. 백엔드에 `/health` 요청을 몇 번 보낸 뒤 1~2분 기다린다.

## 처음 볼 지표

- 백엔드 상태: `up`
- 요청: 요청률, 5xx 오류율, 경로별 rolling p95
- LLM: 모델별 p95, 오류, 재시도, 입력·출력 토큰
- 비용: 실제 계약 단가를 설정한 경우의 추정 비용
- 메모리: 캐릭터별 검색 횟수·평균 검색 결과
- 음성: STT·TTS 지연시간과 fallback

## 알림 순서

1. `up == 0`이 2분 이상 지속
2. 충분한 요청이 있는 시간대에 5xx 오류율이 5% 초과
3. timeout 또는 429가 반복
4. 정상 p95 기준을 측정한 뒤 지연시간 회귀 알림

현재 p95는 백엔드 프로세스의 최근 최대 10,000개 표본 기준이다. 백엔드 재시작 시
표본은 초기화되지만 이미 Grafana Cloud에 전송된 시계열은 Cloud 보존 정책에 따라 남는다.
